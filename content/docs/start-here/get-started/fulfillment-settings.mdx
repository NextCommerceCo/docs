## Fulfillment Locations

Navigate to **Settings > Fulfillment** to add or edit fulfillment locations in your store.  A Location is equivalent to a fulfillment provider's physical warehouse.

Enter a name for the location and choose its **Processing By** integration. Choose **Manual** if your team handles fulfillment directly. Open the location to manage its **Location Address** and **Destination Countries**.

Set up **Allowed Destination Countries** to define which countries this Location can serve, and to give orders from those countries priority routing to this Location.  This field is the highest-priority input to [Location-Based Routing](/docs/features/fulfillment-guide/location-based-routing) — leaving it empty means the Location serves every country but isn't prioritized for any.  Note: the Location's name (e.g. "US Warehouse") has no effect on routing; only the Allowed Destinations list does.

For automated fulfillment by [Shipstation](/docs/apps/shipstation) or another supported integration, set up the corresponding **App** first, then return to the Location setup to update the **Processing By** setting.

<Callout type="success" title="Preparing to Go Live?">

Physical-product stores need at least one fulfillment location and one shipping method with pricing in each selling currency. If an app such as ShipStation or Shop Sync handles fulfillment, return to the location after app setup and confirm **Processing By** points to the correct integration.

</Callout>

## Shipping Methods

Offer multiple shipping methods, and set fees for each method in multiple currencies for your store's customers.

### Set Up Shipping Methods

Navigate to **Settings > Fulfillment > Add Shipping Method**.

Configure the shipping method details:

* **Name** - used for reference on the Dashboard and throughout the store, this value is also visible to customers in the storefront checkout flow.  Note, if your store supports multiple locales and languages, you can edit each name individually.
* **Code** - used to reference this shipping method on the API.
* **Description** - shows in the storefront checkout flow as a brief description of the shipping method.
* **Destination Countries** - the countries this shipping method can ship to.
* **Delivery Time** - a delivery time estimate to be shown to customers in the store checkout flow.

Shipping methods must cover the customer's destination country and have pricing in the order currency.

<Callout type="info">

For orders created on the [Admin API](https://developers.nextcommerce.com/docs/admin-api) a shipping method can be passed into the **`shipping_code`** parameter.  \
\
Alternatively, a custom shipping price may be passed on the API to override the shipping method's default price, using the **`shipping_price`** parameter.

</Callout>

Next, set up Pricing for your Shipping Method, by configuring the following:

* **Currency** - the currency that applies to the shipping method pricing
* **Price Per Order** - used to set a shipping price for the entire order

All stores use [single-page checkout](/docs/start-here/get-started/checkout-settings-and-policies#checkout-layout).

### Check Shipping by Market

Go to **Settings > Markets**, open a market, and choose **Manage** beside **Shipping & Fulfillment**. Review the shipping methods and fulfillment locations serving that country, and confirm shipping prices in the market's currency.

Place a test order to check shipping availability, price, and fulfillment routing before launch.

### Fulfillment Settings

Toggle whether orders should automatically be sent to your integrated Location.

Optionally configure an **Automatic fulfillment processing delay** to allow orders to remain in **Confirmed** status for a set number of hours, before being transitioned to **Processing** status and sent to fulfillment locations.

This setting is useful if your customers often wish to modify or cancel their orders, or update their address details, soon after placing them.

Check out the Orders Guide for more information on order [Fulfillment Status Changes.](/docs/manage/orders/order-statuses#fulfillment-statuses)
